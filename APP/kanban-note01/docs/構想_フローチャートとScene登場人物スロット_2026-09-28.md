## 2. 利用者の要望（読み取り）
1. 下書きのイベント（ページ）を、フローチャートの出来事（プロット）に**アタッチ**していく仕組み
2. まずは**一行プロットをフローチャートで縦につなぐ**だけでもよい。そこにページを登録したり、使い回す資料をリンクしたりする
3. 図3の PARTY のように、**アイコンとスロットで、その出来事の登場人物を登録**する
4. その Scene（画面）だけにスコープを決めて、登録した登場人物を**ショートカットに適用**する（その Scene を書くときは Alt+1〜 がその Scene の人物になる）

## 3. Note Story に当てはめると

| 攻略本 | Note Story |
| --- | --- |
| ロール（章） | 章（Roll） |
| チャート `[1] サウネイルの森` | 場所ごとの区切り＝**Scene（柱の場所名）** |
| 手順 ①②③ | **一行プロット**（必須／任意の印） |
| `→ P054` などのページ参照 | **リンク**: 会話ログの場面・下書き（種類＝イベント）・WW（入手するアイテム）・素材 |
| MISSION BATTLE／SUB EVENT／選択肢 | プロットの**バッジ**（種類の印） |
| PARTY（顔アイコン＋空き枠＋「＋」＋同行人） | その時点の**登場人物スロット**（作品の9つの枠から選ぶ。加入・離脱は前の時点との差で自動に出す） |

### データの形（案）
```
nb.flow = {
  rolls: [{ id, title,                       // 章
    charts: [{ id, place,                    // Scene（場所名＝柱）
      party?: { main: castId[], guest: castId[] },  // この区切りの登場人物スロット
      steps: [{ id, text, required: boolean,        // 一行プロット
        badges: ('battle'|'sub'|'choice'|'item')[],
        party?: {…},                                // 途中で加入・離脱したとき
        links: [{ type: 'page'|'draft'|'ww'|'asset', id }] }] }] }] }
```
- 人物は名前ではなく**枠の ID** で持つ（名前を変えても崩れない）
- ページ・下書き・WW は写さず **ID で指す**（使い回しても1か所を直せば全部に効く）

### Scene スコープのショートカット
- フローチャートのプロットから会話ログの場面を開くと、**その時点の PARTY の並びが Alt+1〜・人物パネルの番号になる**
- 作品の9つの枠（全体）→ その Scene の PARTY（スコープ）の順で決める。NPC（その場限りの人物）も、この Scene の枠として持てる
- これは「画面・状態ごとに操作を絞る」（XState の構想）の最初の実例になる

## 4. 作る順番（案）
1. **フローチャートの一覧**（作品ページに新しいタブ）: 章 → Scene（場所名）→ 一行プロットを縦の線でつなぐ。足す・並べ替える・必須／任意
2. **リンク**: プロットに会話ログの場面・下書き・WW を付ける（押すと開く）
3. **PARTY スロット**: 作品の登場人物の顔アイコンを枠に並べる（仲間＋同行人）。加入・離脱を自動で表示
4. **Scene スコープ**: その場面を開いている間は、PARTY の並びを Alt+番号・人物パネルに使う
5. バッジ（ミッションバトル・サブイベント・選択肢・入手物）と、KeyDeck のボタン面への反映

## 5. JSON の形（2026-09-28 追記: 利用者「プロットに JSON を使い、資料のパスをスロットにアタッチしていく構造でいいか」）

**よい。** 今（プロット作成と関連資料の紐付け）と将来（ゲームの進行フローそのもの）を、同じ形で続けられるよう、次の3つを最初から入れておく。

1. **ブロックに種類（type）を持たせる**: 今は `plot` だけ。将来 `novel`（ノベル）・`adv`（アドベンチャー）・`cg`（一枚絵）・`sim`（シミュレーション）・`battle`（バトル）・`map`（マップ）を足す。知らない種類が来ても消さずに残す
2. **スロットは名前つきの箱**: `slots.party`・`slots.pages`・`slots.materials`…。将来の種類ごとに決まったスロットを足す（例 `novel` なら `background`（背景）・`talk`（会話）・`bgm`）。どの種類にどのスロットがあるかは、型の定義（スキーマ）で決める
3. **資料はパスを写さず「参照」で持つ**: 参照には種類を書く
   - アプリの中の物: `page:<作品ID>/<場面ID>`・`draft:<ID>`・`ww:<ID>`・`cast:<枠ID>`（名前を変えても崩れない）
   - 公開している素材: `url:/deliveries/…/xxx.webp`（どの端末でも見られる）
   - PC の中のファイル: `file:C:\…`（PC でだけ開ける。タブレット・スマホでは名前だけ出す）
   - 形の決まった資料には型名を付ける: `{ "ref": "…", "schema": "asset.image.v1" }`

### 今（プロット用）の1ブロック
```json
{
  "id": "n_01",
  "type": "plot",
  "text": "倒れている兵士に話しかける",
  "required": true,
  "place": "サウネイルの森",
  "slots": {
    "party": { "main": ["slot_1"], "guest": [] },
    "pages": [{ "ref": "page:nb_xxx/p1" }],
    "drafts": [{ "ref": "draft:draft-abc" }],
    "materials": [{ "ref": "url:/deliveries/hajimari_defense/trpg-loc-secret-base-morning.webp", "schema": "asset.image.v1" }]
  },
  "next": ["n_02"]
}
```
全体は `{ "schema": "note_story.flow.v0.1", "titleId": "…", "rolls": [{ "id", "title", "nodes": [ … ] }] }`。作品のデータ（`nb.flow`）に持ち、ファイルとしても書き出せるようにする（novelEngine・CODEX に渡すため）。

### 将来（ゲームの進行フロー）の1ブロック
```json
{
  "id": "n_12",
  "type": "novel",
  "slots": {
    "background": { "ref": "url:/…/forest_night.webp", "schema": "asset.image.v1" },
    "talk": { "ref": "page:nb_xxx/p3", "schema": "talklog.v1" },
    "bgm": { "ref": "file:C:\…\forest.ogg", "schema": "asset.audio.v1" },
    "party": { "main": ["slot_1", "slot_2"], "guest": [] }
  },
  "next": [{ "to": "n_13" }, { "to": "n_20", "when": "choice:1-1" }]
}
```
- `next` は最初は1本の矢印（縦につなぐだけ）。選択肢で分かれるときは `when` 付きで複数にする
- ブロック＝状態、`next`＝移り先 なので、この形はそのまま XState（状態機械）で動かせる。ゲームエンジン（novelEngine）の進行表の元にもなる
- 型の定義（`asset.image.v1`・`talklog.v1`・種類ごとのスロット）は MasterDB に置く（§3-4 の考え方）
