## 3. 構想（まだ作らない）

### 3-1. 下書きの種類 → 記入テンプレート
- いまの種類: 下書き・イベント・キャラクター・世界観
- 使ってみて種類が固まったら、**種類ごとに1つずつ**テンプレートを作る（例: キャラクター＝名前・年齢・口調・立ち絵メモ、イベント＝イベント名・柱・登場人物・目的）
- テンプレートは本文に差し込む形（`[Character_"…"]` などの直書きタグを並べた下地）にすると、あとで解析しやすい

### 3-2. サイドパネルは最小から
- 最初から全部は出さず、**必要な物だけ**サイドパネルに載せていく
- tag も初期は最低限（例: 背景・人物・表情の数個）だけ。足りなくなったら「表示を選ぶ」で足す
- いまの「表示を選ぶ」はこの端末だけの設定。これを**作品ごと**の設定に移すと、作品ごとに最小のセットを持てる

### 3-3. Project 開始時の Template START（複数）
- 新しいタイトルを作るときに「どのセットで始めるか」を選ぶ（例: 空・ノベル標準・TRPG）
- セットの中身: 9つの枠の初期名、下書きの種類、表示する tag、サイドパネルの並び、最初の場面

### 3-4. MasterDB と Store と View（利用者の問い「MasterDB と View や STORE の概念の方が近いかな？」）
**近い。4つの層に分けると整理しやすい。**

| 層 | 役目 | いまの実装で当たる物 |
| --- | --- | --- |
| MasterDB | すべての素。版つきで持つ（tag 辞書、テンプレート、下書きの種類、WW、キャラの型） | タグ辞書 `BOOKS`（NovelGameTag Vol1.1）、`DRAFT_KINDS` |
| Store | MasterDB から選べる棚。人に配る単位（パック） | まだ無い |
| Title への紐づけ（Profile） | その作品で使うパックと版の一覧。「好きな物だけ Title に紐づける」はここ | 作品ごとの登場人物 `nb.cast` だけ |
| View | どの画面にどう見せるか（サイドパネルに何を出すか・順番・端末ごとの見え方） | 「表示を選ぶ」（端末ごと）、候補の Hooks `CANDIDATE_HOOKS`、パネルの開き方 |

- 将来、人に使ってもらうとき: Store から好きなパックを選ぶ → その Title に紐づける → View でサイドパネルに出す、の順
- 大事な点: 作品は MasterDB の**中身を写さず、ID と版で指す**。辞書が新しい版になっても、作品側は自分の版を使い続けられる

## 4. キー入力モニターと、端末ごとのショートカット（2026-09-28 追記）

きっかけ: Lenovo のタブレットで Alt+1（キャラクターのセリフ）が効かない。Android のスマホと PC では効く。

### 4-1. 今回作った物: キー入力モニター（見るだけ）
- 見出しの右のキーボードのアイコンで開く、四角い浮いた窓（`src/v21/KeyMonitor.tsx`）。タイトルの帯をつかんで動かせる（位置は端末ごとに覚える）
- 押したキーの信号を出す: `key`・`code`・`keyCode`・Ctrl/Alt/Shift/Meta・AltGr・長押しのくり返し・日本語入力の変換中かどうか。文字が入るときは `beforeinput`（inputType と入った文字）、変換の始まり・終わりも出す
- いちばん上に、最後に押した組み合わせ（例 `Alt+Digit1`）と、**いまの会話ログの Alt+番号 として受け取れるか**（受け取れないなら理由）
  - 会話ログは「Alt が押された印（altKey）が true」で「code が Digit1〜9」のときだけ動く。Android のタブレットでは、日本語入力が先に受け取る（keyCode 229）、code が空で来る、Alt の印が落ちる、などで外れることが多い
- 「コピー」で端末の情報と記録を文字にしてコピー（そのまま貼って相談できる）。「一時停止」「クリア」
- 操作は変えない（信号を見るだけで、止めたり書き換えたりしない）

### 4-2. 構想: 端末ごとのショートカット（押したキーをそのまま登録）
- 端末ごとに「操作 → キーの組み合わせ」を持つ（localStorage。例 `{ "desk.split.toggle": "Ctrl+Alt+KeyD", "talk.speak.1": "Alt+Digit1" }`）
- 登録のしかた: 設定で操作を選び「押して登録」→ 次に押したキーの組み合わせを、モニターと同じ形（`chordOf()`）でそのまま保存。信号が取れない組み合わせ（日本語入力が先に取る等）はその場で「この端末では使えません」と出す
- 最初に登録できる操作の候補: 2カラムの切り替え、人物1〜9・ナレーション（いまの Alt+番号 の代わりの組み合わせ）、NAV の直書きタグ
- 既定の組み合わせ（Alt+番号など）はそのまま残し、端末ごとの登録があればそちらを使う
- KeyDeck とつなぐとき: KeyDeck のボタンはこの「組み合わせ」を送るだけにする（KeyDeck 側の許可リストに入っているキーから選ぶ）

### 4-3. 作った物: 設定 → ショートカット（2026-09-28）
- 見出しの歯車のボタン（またはキー入力モニターの「登録へ」）で開く `src/v21/SettingsV21.tsx`、保存と受け取りは `src/v21/shortcuts.ts`
- タブ: PC／Android（縦）／タブレット（横）。**いまの端末で使うタブは、端末の種類と向きで自動で選ぶ**（指で触る端末の縦向き＝Android（縦）、指で触る端末の横向きで幅900px以上＝タブレット（横）、それ以外＝PC）。同じタブレットでも縦なら Android（縦）、横ならタブレット（横）のショートカットが効く。使うタブには緑の丸と「この端末」
- 「押して登録」→ 次に押した組み合わせをそのまま保存（修飾キーだけのあいだは待つ・Esc でやめる）
- 登録できない物: 日本語入力が先に受け取るキー（229／Process）、文字を打つキーだけ（Ctrl・Alt と組み合わせるか、F13・無変換などの特別なキーならよい）
- 同じ組み合わせをほかの操作に登録すると、前の操作から外す
- 登録できる操作: 2カラムの切り替え、キー入力モニター、ナレーション・人物1〜9、直書きタグ3つ
- 登録した組み合わせは既定（Alt+番号 など）より先に受け取る。既定はそのまま使える。2カラムでは、書いている列（カーソルのある方）だけが受け取る
- 保存はこの端末（localStorage）。キーの信号は端末ごとに違うので、登録はその端末で行う
- あわせて: スマホ幅で見出しのボタンがはみ出していたので、ロゴの文字と「戻る」の Ctrl+Z を隠して詰めた

### 4-4. Lenovo タブレットの結果（2026-09-28）
- スクショ（Lenovo タブレット・Chrome・横画面・2カラムの下書き＋キー入力モニター）: 記録は `keydown key="Alt" code="AltLeft" keyCode=18 mods=Alt loc1` と `keyup key="Alt"` の2行だけ。**数字の 1 の信号は1つも来ていない**
- 結論: Lenovo では Alt を押している間の数字キーを、端末（OS かキーボード）が先に受け取っていて、ブラウザに届かない。アプリ側では受け取れないので、設定 → ショートカットのタブレット（横）（縦で使うなら Android（縦））に、届く別の組み合わせを登録して使う
- モニターを直した: 修飾キーを押して離すまでに、ほかのキーの信号が来なかったときは、そう書いて知らせる
- 入れたアプリ（PWA）が縦にしかならない件: PWA の設定（manifest）が `orientation: 'portrait'`（縦に固定）だった。ブラウザのタブでは効かない設定なので、Chrome では横にできていた。`'any'`（端末の向きに合わせる）に変えた。入れたアプリには、Chrome が新しい設定を取り込むまで時間がかかることがあるので、早く直すにはアプリを入れ直す

### 4-5. Lenovo タブレットの続き（2026-09-28、スクショ2枚）
- 図1（Chrome・縦・ホーム）: モニターに `key="Convert" code="Convert" keyCode=0`。**変換キーは届く**。Ctrl や Fn はキーボード側の操作があって使いにくい（利用者）
- 図2（入れたアプリ＝PWA・縦・会話ログ）: モニターに `Alt+Digit1`（Alt+番号: 受け取れる）。**入れたアプリでは Alt+1 が効く**。Chrome のタブで効かなかったのは、Chrome が Alt+数字をタブの切り替えに使っていて、ページまで渡さないため
- 図2では、見出しのメニューの文字が縦に折れていた（縦向きのタブレットは幅が約800px で、上のメニューが入りきらない）
- 対応:
  - 変換・無変換を「押したままのキー」として組み合わせに入れる（`Convert+Digit1` など）。設定 → ショートカットで「変換 + 1」のように登録できる。何も押さずに離すと、変換／無変換だけで登録
  - 注意: 変換だけを何かに登録すると、変換を押した時点でその操作が動くので、「変換 + 数字」と一緒には使わない
  - 幅900px以下（タブレットの縦向きなど）では、上のメニューをやめてスマホと同じ画面下のタブにした

## 5. 横画面のパネルと WW（2026-09-28 追記）

- Alt+1 はまた効かなくなったが、いまは放置（利用者）。横画面ではサイドパネルで代わりにする
- 横画面（PC幅）の会話ログ・下書き: **左＝人物、右＝Scene** を最初から開く。左のNAV＝目次（会話ログ）／一覧（下書き）・人物、右のNAV＝Scene・WW・演出。柱の行・柱ブロックに入ると右のパネルが「柱の候補」になる
- Scene は場所名で対応していく（利用者）
- **WW はアイテム・武器・スキルの置き場として合っている**: World Word＝世界観の用語。作品ごとに、種類（アイテム・武器・スキル・用語）・名前・Dict（読み・説明。無くてもよい）で登録する（`nb.ww`、`src/v21/WwPanel.tsx`）。押すと、書いている行のカーソルの位置に名前を貼る。会話ログ・下書き（PC のパネル・スマホのサイドバー）で共通
- 将来: アイテムリスト・スキルリストから名前を選べるように。MasterDB の考え方（§3-4）では、WW の種類ごとの一覧を MasterDB に置き、作品は使う物を ID で指す
