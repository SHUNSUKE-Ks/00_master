## 1. なぜ作り直すか

Vol1.1 は昔のAI開発で機能を足し続けた結果、1つのメニューに用途の違う画面が並んでいる（利用者談「わかりにくい」）。

### Vol1.1 のメニュー（2026-09-25 のスクショをテキスト化。以後は画像を開かない）

| 区分 | 項目 | 説明文 |
|---|---|---|
| 本体 | ClaudeNote | 技術トピックの素材を拾う（読むだけ） |
| 本体 | InBox | 改善案・相談メモを受ける |
| 本体 | Scenario Board | シナリオTODOを分解する（✓表示中） |
| 本体 | アイディア帳 | 芽生え・ネタ・企画断片を書く |
| 本体 | 会話ログ | 名前とセリフを書く（Alt+1〜9 / KeyDeck） |
| 本体 | ブログ表紙 | Gallery写真を表紙に使う |
| 本体 | Study | Note開発の技術Cardを読む |
| 本体 | DB | DB Hub / Relation原本 |
| 本体 | AllAssets設計室 | Sample MasterDB / DB設計たたき台 |
| Gallery View | Instagram Grid / Pinterest Masonry / Asset Tag DB / Concept DB / AllAssets | 見せ方とDBが同じ段に混ざっている |

問題: **目的（書く・集める・調べる・作る）が1列に混在**しており、ノベル制作の流れ（タイトル → 場面 → 会話）がどこにも無い。

## 2. V2.1 の骨組み

目的を「ノベルゲームのシナリオを書く」に絞り、入口を4つにする。

```
ホーム ─┬─ 続きから書く（最後に書いた会話）
        ├─ よく開く（アクセス回数の多いタイトル・場面）
        ├─ タイトル（最近の作品）
        ├─ 登場人物（続きの作品のキャスト）
        ├─ ギャラリー（最近の画像）
        └─ 書き方（3手順）
タイトル ── 作品のギャラリー（表紙・あらすじ・場面数・会話数）
   └─ 作品ページ ─┬─ 場面（Event）の一覧 → 会話ログで書く
                   ├─ あらすじ
                   └─ 登場人物（番号＝Alt+番号＝KeyDeckのボタン）→ KeyDeckへ書き出し
会話ログ ── 名前とセリフだけを書く舞台（Alt+1〜9で直下に新しいセリフ）
ギャラリー ── 既存のGalleryをそのまま（画像素材）
```

| 用語 | データ上の実体 |
|---|---|
| タイトル（作品） | notebook（アイディア帳・InBox・設定・コメントのノートは除く） |
| 場面（Event） | notebook.pages の1ページ |
| 会話 | page.body（または scenarioLogs）の `名前：「セリフ」` |
| あらすじ | notebook.synopsis（V2.1で追加した任意欄） |
| 登場人物 | notebook.cast（V2.1で追加した任意欄）。無ければページの characters |

## 3. 決めたこと

- **既定は V2.1。** Vol1.1 はそのまま残し、メニュー上部の2タブ（V2.1 / Vol1.1）で行き来する。**切り替えると再読み込みして、ホームから全部やり直す。**
- V2.1 のコードは `src/v21/` にまとめ、Vol1.1 のファイルには入口を足すだけにする（CODEX が Vol1.1 側を並行で触っているため）
- 暗い配色（白い画面は苦手、という利用者の方針）。見出しは明朝体で、作品の空気を出す
- スマホ幅では、ナビゲーションを画面下のタブにする（Android・iPadで親指が届く位置）
- 「よく開く」は端末ごとの localStorage に数える（同期はしない）

### ヘルプ（2026-09-25 追加）

- どの画面でも **Ctrl+/**（スマホ・iPadは右上の **?**）で「この画面でできること」を出す。Esc で閉じる
- 中身は `src/v21/help.ts` の表。画面ごとに、キー・書式（tag）・押して使う操作を並べる。会話ログでは、いまの番号と人物（Alt+番号）も出す
- 操作には「いつ使えるか」（いつでも／入力中／見ているとき）を持たせる。開いた瞬間の状態に合わない操作は薄く出す
- **これは次のアプリで XState を使うための下地。** 共通操作も local 操作に切り離し、画面・画面Phaseで使える操作だけに限定する、という構想（利用者 2026-09-25）の小さな先行例。XState に移るときは、`when` を状態名に置き換える

### 下書きとタグ辞書（2026-09-25 追加）

V2.1 での扱い:

- 作品ページに「下書き」タブを置いた。**何枚でも仮置きできる。本番の場面（notebook.pages）とは別の置き場**（`src/v21/drafts.ts`、いまはこの端末の localStorage だけ）
- 書く道具は旧ノートと同じ書式の関数を使う（`formatScenarioBlock`・`formatCallout`）。人物ボタンは作品の登場人物
- 横の候補は2段のタブ: 1段目 共通／キャラクター／WW、2段目 分類（背景・人物・表情…）。押すとカーソル位置に貼る
- キャラクターのタブは、仮に作品の登場人物を表示している。WW は置き場が未定なので案内だけ（本番と混ぜるかは利用者が検討中）
- タグ辞書は **1冊の本**（`src/v21/dictionaries/NovelGameTag_Vol1.1.json`）。全部は出しきれないので「表示を選ぶ」で出すタグを選ぶ（この端末に保存）
  - 受け取った分: bg（後半6件）・char・face・cg・ui・cam・ev・flag・req・memo の **93件**
  - **未受領**: fx_・mood_・bgm_・se_ の全件、bg_ の前半（貼り付けが途中から始まっていた）
  - 設計（利用者の本より）: tags は演出、control は対象値（target・value）が要る処理に分ける

### 納品の取り込み（2026-09-26 追加）

- 別の制作チャット（例: 「Voice of Cards TRPG title creation」＝GAME08_VoiceOfCards）が作った物語・立ち絵・素材を、`public/deliveries/<id>/delivery.json`（形式 `note_story_delivery` v0.1。NovelEngine の content delivery package の meta に項目名をそろえた）として置く
- ホームの「届いた納品」から **取り込む** → 作品（notebook）ができる。`deliveryId` で二重取り込みを防ぐ
- 作品ページに立ち絵つきの登場人物と「素材（納品）」、会話ログの名前札の左に立ち絵を出す
- 第1号: **はじまりの町の防衛線**（第一章「勇者が旅立つ理由がない朝」）。原本 `GAME08_VoiceOfCards/src/AppScreen/60_Arcade/modes/questTale/scenarios/scenario_hajimari_01.json` を変換スクリプトで移した（本文36行を1文字も変えずに移し、取りこぼしが0であることを検算）
