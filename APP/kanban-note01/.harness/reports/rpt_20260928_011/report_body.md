# V2.1 のギャラリーを新しく（2026-09-28）

## 依頼
- ギャラリーをピンタレスト風から V2.1 に合う画面へ。前のは残す。
- タグのしくみを V2.1 の仕様に合わせて DB と連携。
- 目標: 各端末から写真を入れられ、PC でもアプリから見られる。
- 左のサイドバーを V2 に合わせる。写真ごとに JSON を持ち、小さなコメントをいくつも付けられる。

## できたこと
### 画面（src/v21/GalleryV21.tsx）
- **左サイドバー**: 表示（すべて／お気に入り／この端末だけ／ごみ箱）、作品（件数つき・作品なし）、選んだ作品の登場人物、タグ、クラウドの状態（読み直す・送れなかった写真を送り直す）、「前のギャラリー」。スマホは「絞り込み」ボタンで引き出しとして出る。
- **一覧**: 「＋ 写真を入れる」（何枚でも）。PC は一覧へ落としても入る。左で作品・人物を選んでいれば最初から付く。名前・タグ・コメントで検索、新しい順／古い順。カードには同期の点（緑=クラウド、黄=送信中、赤=失敗、灰=この端末だけ）とコメント数。
- **写真の情報（右）**: 名前、♡、作品（複数可）、登場人物、タグ（タグ DB の Gallery 用と既存タグを候補に出す）、コメント（足す・消す／時刻と端末つき）、JSON を見る・コピー、ごみ箱へ（アプリのダイアログで確認）・戻す。画像を押すと大きく見る（← → で前後、Esc で閉じる）。

### 写真の持ち方（src/v21/photoStore.ts）
1. 端末で選んだ写真を長い辺 2048px の JPEG に縮める（読めない形式はそのまま）。
2. 画像は IndexedDB、情報（画像なし）は localStorage。前のギャラリーは画像も localStorage に入れていて数枚で満杯になっていた。
3. クラウド（Firebase Storage と Firestore の galleryAssets）へ送る。直した情報もクラウドに書く。
4. ギャラリーを開くたびにクラウドを読み直す（ボタンでも）。スマホで入れた写真が PC のアプリで見える。

### 写真の JSON（クラウドの1件）に入るもの
`titleIds`（作品）、`characterRefs`（"<作品ID>:<枠ID>"）、`tags`、`comments`（id・text・createdAt・device）、`favorite`、`deleted`、`device`、`storagePath`、`downloadUrl`、`syncStatus` など。

### 直した不具合
- 他の端末でごみ箱に入れた写真が、クラウドから読むと消えていなかった。
- 読めない形式（PC の HEIC など）で読み込みが止まり得た。
- 写真を直すたびに情報の欄が作り直され、入力中の欄が外れていた。

## 確かめたこと
- 型チェック・本番ビルド成功。
- jsdom 14本すべて PASS（新しいギャラリーのテスト 45件）。テストは Firebase を切ったビルドで、本物のクラウドには書いていない。
- 開発サーバーで PC 幅・スマホ幅の画面を確認。「クラウドから読み直す」は動作（クラウドの写真はいま 0 枚）。

## 残り・注意
- 本番デプロイはまだ。デプロイ後、スマホで1枚入れて PC で読み直す確認が必要。
- Firebase Storage のルールはリポジトリに無く、中身が分からない。送れなかったときは写真の欄に理由が出て、「クラウドへ送る」で再送できる。
- V2.1 全体の見返しは Sub_KanbanNote が担当（ギャラリーのファイルには触れない取り決め）。
