## 一行の判断

```text
自分のアプリの作業を分ける -> Branch
他人のOSSを自分の管理下で改造する -> Fork
一部の完成コミットだけ採用する -> cherry-pick
```

## 今の扱い

- 通常の小さな修正では、ブランチを増やさない。
- 変更が大きい、試作が本体を壊しうる、並行作業を分けたい時だけBranchを検討する。
- Forkは外部OSSを直接直したい時だけ検討する。
- 実際にGit操作をする時は、その時点で対象・目的・戻し方を確認する。
