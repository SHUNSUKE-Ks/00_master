# Web ChatGPT Project / 原本チャット保管

## 質問

Projectの運用方法と、ナレッジにGitのファイルパスを置いた時に毎回そのGitをmemoryとして読めるか。

## 原本の結論

Gitのファイルパスを文字で置くだけでは、そのGitを毎回自動で読めない。

Projectは同じProject内のchatと追加資料を参照するが、毎回すべてを丸読みするのではなく、質問に関係する範囲を取り出して使う。

## 役割分担

| 層 | 置くもの | 役割 |
| --- | --- | --- |
| Project | SolidJS + 状態駆動開発など領域単位 | 会話・資料・方針をまとめる箱 |
| 指示 | 命名規則、技術方針、出力形式、禁止事項 | 新規Chatにも効かせる共通ルール |
| ナレッジ | project_overview、architecture、用語集、仕様書 | AIに毎回参照させたい判断材料 |
| Git | 実装コード、履歴、Issue、README | 正本・変更管理 |
| Chat | 依頼ごとの設計、実装、review、調査 | 作業log |

## Project単位の例

```text
01_カプセルモンスター
02_VacareNote
03_PlotNest
04_SolidJS_基盤研究
```

短い調査・一回で終わる質問はProject外で行い、採用した結論だけProject資料へ保存する。

## Knowledgeの最小セット

```text
project_overview.md
system_architecture.md
development_rules.md
current_status.md
glossary.md
```

## Git連携の選択肢

1. パス記載: ローカルpathやGitHub URLを資料に書く。場所の案内だけ。
2. 資料追加: 要約MarkdownをProject資料へ追加する。
3. GitHub連携: 接続済みGitHubから必要時に資料を明示して読む。

## 注意

Project memoryは便利だが、厳密な全ファイル読込保証ではない。実装時はGitのmainを基準にし、概要・構造・現在状態の資料を明示して読む。

## 原本の推奨

```text
Git = 正本
Project資料 = 設計インデックス
Chat = 作業履歴
```
