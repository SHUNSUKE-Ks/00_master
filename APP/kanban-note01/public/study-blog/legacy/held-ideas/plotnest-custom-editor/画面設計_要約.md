# PlotNest / 画面設計の要約

> 状態: 保留構想。独自DSLを含むCustomEditorのための画面案。

## 核心

この構想は「創作メモ」「Relation管理」「ノード接続」「将来JSON出力」「API化」「演出DB蓄積」を、混ぜずに画面ごとへ分割するものだった。

原本: [画面設計の前提](./原本チャット_保管.md#画面設計の前提)

## 画面一覧

### 制作入口

| 画面 | 役割 |
| --- | --- |
| Dashboard | 作品一覧、最近編集、進行状況 |
| InBox | 断片アイディアの放り込みと後の整理 |
| EventEditor | Scene / Eventを書くDSL入力と構造プレビュー |

原本: [全体構造](./原本チャット_保管.md#全体構造screen一覧)、[InBox](./原本チャット_保管.md#inbox最重要)、[EventEditor](./原本チャット_保管.md#eventeditor-dsl入力)

### DBとRelation

| 画面 | 役割 |
| --- | --- |
| CharacterDB | キャラクター詳細と関連Eventタイムライン |
| LocationDB | 場所、初登場イベント、時間帯tag |
| Camera / PromptDB | 構図、カメラワーク、生成プロンプト |
| RelationView | Event、Character、Locationをノードで結ぶView |

原本: [CharacterDB〜RelationView](./原本チャット_保管.md#dbとrelation)

### 出力と環境

| 画面 | 役割 |
| --- | --- |
| ExportCenter | Runtime / Relation / Prompt / AssetSpec JSON出力 |
| Settings | PC/Android別レイアウト、Keymap、View設定 |

原本: [ExportCenterとSettings](./原本チャット_保管.md#出力と設定)

## UI思想

### PC

- 情報量を優先する。
- 3カラムを許可する。
- 編集、一覧、詳細プレビューを同時に表示する。

### Android

- 1カラムを基本にする。
- ボトムシート、FAB、切替Viewで密度を制御する。

原本: [レイアウト思想](./原本チャット_保管.md#レイアウト思想)

## 最小化の順序

1. InBox + EventEditorだけの最小版
2. Character / Location DBとRelation
3. JSON出力仕様の確定

原本は `A -> B -> C` を安全な順序としていた。独自DSLは難度が高いため、現行では「既存JSON Schemaに沿うEditor」が先である。

原本: [重要な決断](./原本チャット_保管.md#重要な決断)
